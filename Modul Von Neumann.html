B. Dimensi Profil Lulusan (DPL)

DPL1
Penalaran Kritis. Mengidentifikasi, menganalisis, dan memecahkan masalah terkait alur data dan instruksi pada komponen arsitektur Von Neumann dalam mengeksekusi program atau gim.
DPL2
Kreatif. Merekonstruksi dan memodelkan simulasi siklus instruksi (Fetch-Decode-Execute) secara visual dan digital dengan analogi logika pemrograman.
DPL3
Kolaboratif / Gotong Royong. Bekerja sama dalam tim mengeksplorasi peran masing-masing unit pemrosesan komputer melalui pembagian tugas simulasi interaktif.
DPL4
Kemandirian. Memanfaatkan teknologi kecerdasan buatan (AI) dan internet secara bertanggung jawab untuk mencari referensi teknis dan memverifikasi konsep secara mandiri.

Mulai dari mana?

Uraian Materi Pelajaran

Arsitektur Von Neumann adalah desain arsitektur komputer teoritis yang diperkenalkan oleh matematikawan John von Neumann pada tahun 1945. Model ini menjadi fondasi hampir seluruh komputer modern: PC, smartphone, dan konsol gim.

Prinsip utama: Stored-Program Concept

Sebelum konsep ini, komputer diprogram ulang dengan mengubah kabel fisik atau sakelar sirkuit secara manual (seperti ENIAC). Von Neumann mengusulkan agar program (instruksi baris kode) dan data disimpan bersama di memori utama (RAM) yang dapat dialamati secara digital.

Siklus instruksi (Instruction Cycle)

Setiap kali software dieksekusi, CPU mengulang empat tahap ini tanpa henti. Lihat langsung di tab Simulasi.

Von Neumann Bottleneck dalam pengembangan gim

Data dan instruksi berbagi bus transmisi yang sama antara CPU dan memori. Kecepatan CPU modern sering kali harus menganggur (idle) menunggu kiriman data dari RAM yang jauh lebih lambat. Fenomena ini disebut Von Neumann Bottleneck.

Developer PPLG perlu memahami ini agar mampu merancang struktur data efisien, meminimalkan memory footprint, dan memanfaatkan cache multi-level (L1, L2, L3) agar gim atau aplikasi tidak mengalami frame drop.

Mesin Von Neumann Mini

Program di RAM mengurangi Player_Health sebesar 20, lalu menampilkan Game_Over bila nilainya sudah tidak lebih dari 0. Jalankan satu tahap demi satu tahap dan perhatikan komponen yang menyala.

Catatan eksekusi

Simulator Von Neumann Bottleneck

Satu frame gim butuh dua hal: waktu hitung CPU dan waktu memindahkan data lewat bus. Frame baru selesai setelah yang lebih lambat tuntas. Naikkan clock CPU, lalu naikkan bandwidth atau cache, dan bandingkan hasilnya.

Model sederhana: 24 juta siklus CPU per frame; transfer dihitung dari data yang tidak ditemukan di cache.

Human Von Neumann Machine

Tulis nama anggota kelompok (satu nama per baris, 4–6 orang), lalu acak perannya. Setiap peran punya naskah singkat untuk memerankan instruksi Player_Health = Player_Health - 20.
